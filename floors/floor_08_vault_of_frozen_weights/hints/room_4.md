The report must compare before and after on identical batches. Draw one integer from the generator (`seed = int(torch.randint(0, 2**31 - 1, (1,), generator=generator))`) and build a fresh `torch.Generator().manual_seed(seed)` for each of the four `evaluate_loss` calls. Then `delta_old = old_after - old_before`, same for new.
---
The three copies all start with `copy.deepcopy(model)`. Full: set `p.requires_grad_(True)` on everything and call `finetune`. LoRA: set everything False, `inject_lora(copy_, r=r, alpha=alpha)`, then `finetune` (it only sees the trainable adapter params). Replay: two `make_batches` streams (`batch_size - n_old` rows from `new_text`, `n_old = round(batch_size * replay_fraction)` rows from `old_text`), `torch.cat` them each step, and run the AdamW loop over all parameters yourself.
---
For the prophecy, think about what each strategy is allowed to move and whether the loss has any reason to protect the chronicles. Full fine-tune at lr 1e-3 moves everything, far, with no reason to remember: the worst. LoRA at the same lr moves 8% of the weights in a rank-8 subspace: less damage, still forgetting. lr 1e-4 moves everything a tenth as far: it forgets more than the threshold here, but a lot less than lr 1e-3. Replay is the only one whose loss still contains chronicles text: least, and under the threshold.
