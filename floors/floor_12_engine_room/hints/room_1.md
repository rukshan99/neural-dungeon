The key and value of token j at every layer depend only on tokens 0..j (causal masking guarantees it), so once computed they never change. Keep them: one `(k, v)` pair per layer, each `(B, H, T_past, hd)`. A decode step feeds ONE token through the network and appends its k and v to every layer's pair. The number of forward passes stays the same; the number of tokens inside each pass drops from T to 1.
---
Inside `attention_with_cache`: `q, k, v = block.attn.c_attn(x).split(C, dim=2)`, each reshaped with `.view(B, T_new, H, hd).transpose(1, 2)`. Then `k = torch.cat([k_past, k], dim=2)` (same for v). Scores are `q @ k.transpose(-2, -1) / sqrt(hd)`, shape `(B, H, T_new, T_total)`. The mask for T_new > 1: `k_pos > q_pos` where `q_pos = arange(T_past, T_total)[:, None]` and `k_pos = arange(T_total)[None, :]`. Finish with softmax, `@ v`, transpose back, `c_proj`. In `forward_with_cache` the positions are `torch.arange(past_len, past_len + T_new)`.
---
`generate_with_cache`: `n = min(max_new_tokens, block_size - T)`; `logits, caches = forward_with_cache(model, idx, 0, None)` (prefill); then `for step in range(n)`: if `step > 0`, `logits, caches = forward_with_cache(model, idx[:, -1:], idx.shape[1] - 1, caches)`; `next_id = logits[:, -1].argmax(-1, keepdim=True)`; `idx = torch.cat([idx, next_id], 1)`. Decorate with `@torch.no_grad()`. The whole function is about ten lines; if yours re-embeds the prompt at every step, the embedding-count trial will say so.
