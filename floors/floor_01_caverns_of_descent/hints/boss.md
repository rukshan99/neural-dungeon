Phase 1 is three branches: `if step < warmup_steps: return lr_max * step / warmup_steps` (never reached when warmup_steps is 0), `if step >= total_steps: return lr_min`, otherwise `progress = (step - warmup_steps) / (total_steps - warmup_steps)` and `lr_min + 0.5 * (lr_max - lr_min) * (1 + math.cos(math.pi * progress))`. Phase 2: for each candidate, run `steps` plain GD steps from a *copy* of x0 and mark it dead as soon as `loss_fn(x)` is not finite or exceeds `loss_fn(x0)`; return `max(survivors)` or raise ValueError.
---
Phase 3: plain GD at any single learning rate cannot win, because the a = 1000 wall forces lr < 0.002 and the a = 1 floor then moves by only 0.2% per step. Adam sidesteps this: its per-coordinate normalisation makes early steps about `lr` in size in *every* coordinate, so both directions travel at the same speed. But a constant lr leaves Adam jittering near the bottom; decay it to 0 with your Phase 1 schedule so the last steps are tiny.
---
A complete Phase 3: `x = np.array(x0, float); state = {}; warmup = max(1, max_steps // 20)`, then `for step in range(max_steps): g = grad_fn(x); lr = cosine_with_warmup(step, max_steps, warmup, lr_max=0.1, lr_min=0.0); x, state = adam_step(x, g, state, {"lr": lr})`, and return x. With these numbers the quadratic is under 1e-3 after ~110 of its 2000 steps and Rosenbrock is under 1e-2 after ~700 of its 5000. The same code, untouched, handles both.
